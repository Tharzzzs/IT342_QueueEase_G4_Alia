EXECUTIVE SUMMARY
1.1 Project Overview
QueueEase is a service-oriented queue management system designed to digitally organize customer queues for service centers such as offices, clinics, and customer service counters. The system allows users to register, authenticate, join queues, and monitor their queue status, while authorized staff and administrators manage queue operations and system data.
QueueEase is implemented using a Spring Boot backend that follows a layered architecture, a React-based web application, and an Android mobile application. The system integrates Firebase Firestore as its primary database, incorporates JWT-based authentication, Google OAuth login, email notifications, file uploads, and sandbox payment gateway integration, in compliance with course requirements.

1.2 Objectives
1. Develop a complete Queue Management that satisfies all required IT342   system features
2. Implement secure authentication using JWT, BCrypt, and Google OAuth login
3. Apply role-based access control for administrators, staff, and regular users
4. Integrate external services including email delivery, file uploads, and payment gateway (sandbox mode)
5. Ensure the system follows a structured backend architecture with proper separation of concerns
6. Deliver a responsive and cross-platform application accessible via web and mobile devices




1.3 Scope
Included Features
• User registration, login, logout, and authenticated session management• Google OAuth login with internal JWT generation• Role-based access control (Admin, Staff, User)• Service center and queue management (full CRUD operations)• Real-time or near real-time queue updates• File upload for service-related documents or attachments• Email notifications for account and system events• Sandbox payment gateway integration (where applicable)• External public API integration for additional system data• Responsive web interface and Android mobile application• Firebase Firestore database with normalized data structure
Excluded Features
• AI-based decision making
• Production-mode payment processing
• Multi-language support

Manual queuing systems cause long wait times, inefficient service handling, and poor customer experience.

6.0 DATABASE DESIGN
6.1 Entity Relationship Diagram



Detailed Relationships:
One-to-Many: User → Service Centers: A single user (with Staff/Admin role) can register and manage multiple service centers.     
One-to-Many: User → Queue Entries: A customer can join multiple queues (one at a time or historically)
One-to-Many: Service Center → Queue Entries: Each business location manages its own list of customers waiting in line.
One-to-Many: Service Center → Files: Each center can have multiple uploaded documents or images related to its services.
One-to-One: Queue Entry → Payment: Each specific queue transaction is linked to a single sandbox payment record.

Key Collections:
users - User accounts and authentication
service_centers - Business/Service center registry and management
queue_entries - Real-time customer queue tracking
payments - Transaction records for sandbox payments
files - Metadata for service-related document uploads
refresh_tokens - JWT refresh tokens for session management

Collection Structure Summary:
users: id, email, password_hash, firstname, lastname, role, created_at
service_centers: id, owner_id, name, description, location, category, status
queue_entries: id, center_id, user_id, position, status, joined_at
payments: id, user_id, entry_id, amount, status, processed_at
files: id, center_id, file_url, file_name, uploaded_at
refresh_tokens: id, user_id, token, expires_at
